# 배포/접속 방식 수동 회귀 테스트 기준 문서

## 문서 목적

- 개인용 todo 앱의 실행/접속 방식 검증 문서
- 자동 테스트가 아니라 사람이 직접 앱 실행과 접속을 확인하는 수동 테스트 기준
- 로컬 실행, 같은 네트워크 접속, Tailscale 접속을 구분해 검증한다.

---

## 공통 통과 기준

- 앱이 로컬에서 정상 실행되어야 한다.
- API key가 없어도 앱이 죽지 않고 안내되어야 한다.
- `.streamlit/secrets.toml`은 Git에 포함되지 않아야 한다.
- `todos.json` / `roles.json`은 호스트 PC 기준으로 저장되어야 한다.
- 클라이언트 PC에는 데이터 파일이 저장되지 않아야 한다.
- 공개 인터넷에 인증 없이 노출하지 않아야 한다.
- 백업/내보내기 기능이 정상 동작해야 한다.

---

## 테스트 케이스

### TC-01. 로컬 실행

**명령:**
```powershell
cd c:\dev\todo_ai_app
.\.venv\Scripts\Activate.ps1
streamlit run app.py
```

| 항목 | 내용 |
|---|---|
| 접속 URL | `http://localhost:8501` |
| 기대 결과 | 앱 정상 접속 |
| 확인 1 | 오늘 할 일 / 주간 보기 / 전체 보기 / 검색 정상 |
| 확인 2 | 백업/내보내기 정상 |
| 확인 3 | 터미널 종료 시 접속 종료 |

---

### TC-02. 같은 네트워크 접속 실행

**명령:**
```powershell
streamlit run app.py --server.address 0.0.0.0 --server.port 8501
```

| 항목 | 내용 |
|---|---|
| 기대 결과 | 호스트 PC 앱 실행 성공 |
| 확인 | 같은 Wi-Fi / 내부 네트워크의 다른 PC에서 `http://호스트PC_IP:8501` 접속 가능 |
| 실패 조건 | `--server.address 0.0.0.0` 없이 실행해 다른 PC 접속 안 됨 |

---

### TC-03. 호스트 PC IP 확인

**명령:**
```powershell
ipconfig
```

| 항목 | 내용 |
|---|---|
| 확인 항목 | Wi-Fi 또는 이더넷 어댑터의 IPv4 주소 |
| 기대 결과 | `192.168.x.x` 형태의 IP 확인 |
| 접속 테스트 | 클라이언트 PC에서 `http://192.168.x.x:8501` 접속 가능 |

---

### TC-04. Windows 방화벽

**조건:** 다른 PC에서 접속이 안 되는 경우

| 확인 항목 | 내용 |
|---|---|
| Python 접근 허용 | Windows Defender 방화벽에서 Python 허용 여부 |
| 개인 네트워크 허용 | 공용이 아닌 개인 네트워크 허용 여부 |
| 포트 8501 | 인바운드 차단 여부 |
| 환경 확인 | 회사/학교 네트워크의 장치 간 접속 차단 여부 |

---

### TC-05. 클라이언트 PC에서 todo 추가

**조건:** 클라이언트 PC에서 앱 접속 후 todo 추가

| 항목 | 내용 |
|---|---|
| 기대 결과 | 클라이언트 PC에서 todo 추가 가능 |
| 확인 1 | 데이터가 호스트 PC의 `todos.json`에 저장됨 |
| 확인 2 | 클라이언트 PC에는 `todos.json`이 생성되지 않음 |

---

### TC-06. Tailscale IP 직접 접속

**조건:**
- 호스트 PC와 클라이언트 기기 모두 Tailscale 로그인
- 같은 tailnet에 있음
- 호스트 PC에서 Streamlit 앱 실행 중

**접속 URL:**
```
http://호스트PC_Tailscale_IP:8501
```

| 항목 | 내용 |
|---|---|
| 기대 결과 | 다른 네트워크에서도 접속 가능 |
| 확인 1 | todo 추가 시 호스트 PC `todos.json`에 반영 |
| 확인 2 | 공개 인터넷 URL 없이 접속 |
| 실패 조건 | 서로 다른 계정 또는 tailnet에 로그인되어 있음 |

---

### TC-07. MagicDNS 접속

**조건:** Tailscale MagicDNS 사용 가능

**접속 URL:**
```
http://호스트장치이름:8501
```

| 항목 | 내용 |
|---|---|
| 기대 결과 | MagicDNS 이름으로 접속 가능 |
| 대안 | 실패 시 TC-06(Tailscale IP 직접 접속)으로 대체 |

---

### TC-08. Funnel / 포트포워딩 금지 확인

| 확인 항목 | 기대 결과 |
|---|---|
| `tailscale funnel` | 사용하지 않음 |
| 공유기 포트포워딩 | 8501 포트를 인터넷에 공개하지 않음 |
| public URL | 앱을 노출하지 않음 |

---

### TC-09. API key / secrets

**조건:** Mindlogic API key가 호스트 PC에만 설정됨

| 항목 | 내용 |
|---|---|
| 기대 결과 | 클라이언트 PC에 API key 불필요 |
| 확인 1 | AI 자연어 입력이 호스트 PC secrets/env 기준으로 동작 |
| 확인 2 | `.streamlit/secrets.toml`이 Git에 포함되지 않음 확인 (`git log -- .streamlit/secrets.toml`) |

---

### TC-10. 데이터 저장 위치

| 확인 항목 | 기대 결과 |
|---|---|
| 파일 위치 | `todos.json` / `roles.json`이 호스트 PC에 있음 |
| 다른 PC 접속 | 호스트 PC 파일이 사용됨 |
| 호스트 PC 변경 시 | 기존 데이터가 보이지 않을 수 있음 인식 |

---

### TC-11. 백업/내보내기

**조건:** 네트워크 또는 Tailscale 접속 상태

| 확인 항목 | 기대 결과 |
|---|---|
| 백업/내보내기 버튼 | 정상 동작 |
| 다운로드 파일 | secrets / API key 미포함 확인 |

---

### TC-12. 앱 종료

**조건:** 호스트 PC 터미널에서 `Ctrl+C`

| 항목 | 내용 |
|---|---|
| 기대 결과 | 호스트 PC 앱 종료 |
| 확인 | 클라이언트 PC 접속도 끊김 |

---

## 실패 패턴

| 실패 패턴 | 연관 TC |
|---|---|
| `localhost`는 되지만 다른 PC 접속 안 됨 | TC-02 |
| `--server.address 0.0.0.0` 없이 실행 | TC-02 |
| 호스트 IP를 잘못 입력 | TC-03 |
| 포트 `:8501`을 빠뜨림 | TC-03 |
| Windows 방화벽에서 차단됨 | TC-04 |
| 회사/학교 네트워크에서 장치 간 통신 차단 | TC-04 |
| Tailscale에서 서로 다른 계정/tailnet에 로그인 | TC-06 |
| Funnel 또는 포트포워딩으로 앱을 공개 노출 | TC-08 |
| 클라이언트 PC에 데이터가 저장된다고 오해 | TC-05, TC-10 |
| `secrets.toml`을 Git에 올림 | TC-09 |

---

## 개발 원칙

- 개인용 앱은 공개 배포보다 안전한 개인 접속을 우선한다.
- 로컬 / 네트워크 / Tailscale 접속은 호스트 PC 저장 구조를 전제로 한다.
- 클라우드 배포는 외부 DB 또는 persistent storage 검토 이후 진행한다.
- 배포보다 데이터 안정성과 백업을 우선한다.
