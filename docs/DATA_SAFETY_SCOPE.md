# 데이터 안전성 개선 1차 범위 문서

## 기능 목표

- JSON 파일 손상 또는 읽기 실패 시 앱이 중단되지 않게 한다.
- `todos.json` / `roles.json` 파일이 없을 때 안전한 빈 데이터로 시작한다.
- JSON 구조가 예상과 다를 때 사용자에게 명확히 안내한다.
- 손상된 원본 파일을 임의로 덮어쓰지 않는다.
- SQLite 전환 전까지 JSON 저장 구조의 실사용 안정성을 높인다.

---

## 1차 구현 범위

| 항목 | 설명 |
|---|---|
| `todos.json` 읽기 실패 처리 | `JSONDecodeError`, 파일 없음, 타입 불일치 안전 처리 |
| `roles.json` 읽기 실패 처리 | `JSONDecodeError`, 파일 없음, 타입 불일치 안전 처리 |
| `JSONDecodeError` 처리 | 파싱 실패 시 앱 중단 대신 경고 표시 |
| 파일 없음 처리 | 파일이 존재하지 않을 때 빈 목록으로 안전하게 초기화 |
| 예상 타입 불일치 처리 | `todos.json`/`roles.json`이 `list`가 아닐 때 경고 |
| 손상 시 경고 표시 | `st.warning()`으로 사용자에게 안내 |
| 손상 파일 자동 수정 금지 | 원본 파일은 읽기 전용으로만 다룸 |
| 백업/내보내기 안내 | 오류 시 기존 백업 기능 사용 안내 |

### 오류 유형 분류

| 오류 유형 | 처리 방법 |
|---|---|
| 파일 없음 (`FileNotFoundError`) | 빈 목록 반환, 조용한 초기화 (정상 케이스) |
| JSON 파싱 실패 (`JSONDecodeError`) | 경고 표시, 빈 목록 반환, 파일 유지 |
| 읽기 권한 오류 (`PermissionError` 등) | 경고 표시, 빈 목록 반환 |
| 타입 불일치 (list 기대, dict 수신) | 경고 표시, 빈 목록 반환 |

## 1차 제외 범위

| 제외 항목 | 이유 |
|---|---|
| 자동 복구 | 데이터 손실 위험, 사용자 확인 필요 |
| 손상 파일 자동 백업 | 저장 로직 복잡도 증가 |
| 복원 기능 | 별도 브랜치에서 다룸 |
| SQLite 전환 | 다음 단계 작업 |
| Supabase 전환 | 장기 로드맵 |
| 파일 lock 처리 | 단일 사용자 환경 가정 |
| 동시 접속 충돌 처리 | 단일 사용자 환경 가정 |
| 암호화 저장 | 이번 단계 범위 밖 |

## 데이터 안전 원칙

- 읽기 실패 시 원본 파일을 덮어쓰지 않는다.
- `save_todos()` / `save_roles()`는 명시적 저장 작업에서만 호출한다.
- `load_todos()` / `load_roles()`가 실패해도 앱 전체가 죽지 않아야 한다.
- 손상된 파일을 빈 목록으로 조용히 대체하지 않는다 — 사용자에게 알린다.
- 사용자에게 "파일을 확인하거나 백업에서 복원하라"는 안내를 보여준다.
- API key나 secrets 파일은 데이터 안전 처리 대상이 아니다.

---

## 사용자 안내 방향

오류 메시지는 짧고 명확해야 한다. traceback을 사용자 화면에 노출하지 않는다.

### 안내 메시지 예시

```
todos.json을 읽을 수 없습니다. 파일이 손상되었을 수 있습니다.
앱은 임시로 빈 목록을 사용합니다. 원본 파일은 변경하지 않았습니다.
백업/내보내기 기능으로 보관한 파일이 있다면 수동으로 확인해 주세요.
```

### 표시 방법

| 상황 | 표시 수단 |
|---|---|
| 파일 없음 | 표시하지 않음 (정상 초기화) |
| JSON 파싱 실패 | `st.warning()` |
| 타입 불일치 | `st.warning()` |
| 읽기 권한 오류 | `st.warning()` |

## 수동 검증 기준

| 검증 항목 | 확인 내용 |
|---|---|
| `todos.json` 없음 | 앱이 정상 실행되는지 |
| `roles.json` 없음 | 앱이 정상 실행되는지 |
| `todos.json` 깨진 JSON | 앱이 죽지 않고 경고가 표시되는지 |
| `roles.json` 깨진 JSON | 앱이 죽지 않고 경고가 표시되는지 |
| `todos.json`이 `list`가 아닌 `dict` | 사용자 안내가 표시되는지 |
| `roles.json`이 `list`가 아닌 `dict` | 사용자 안내가 표시되는지 |
| 손상 파일 자동 덮어쓰기 | 손상된 파일이 변경되지 않는지 |
| 정상 파일 | 기존처럼 정상 로드되는지 |
| 기능 회귀 | 오늘 할 일, 전체 보기, AI 입력, 백업/내보내기 정상 동작 |

## SQLite 전환과의 관계

- 이번 단계는 SQLite 전환이 아니다.
- JSON 데이터가 안정적으로 읽히고 백업 가능한 상태여야 SQLite migration이 안전하다.
- 이번 단계는 SQLite 전환 전 데이터 품질을 확인하는 준비 단계다.

### 현재 저장 로드맵

```
1. todos.json (현재) ← 이번 단계: 안정성 강화
2. SQLite           ← 다음 단계
3. Supabase         ← 장기 목표
4. Auth + user_id   ← 멀티유저 목표
```

## 개발 원칙

- 작은 단위로 구현하고 검증 후 커밋한다.
- `app.py` 단일 파일 구조는 당분간 유지한다.
- 저장 구조는 변경하지 않는다.
- 데이터 손상 시 자동 덮어쓰기 금지.
- 복원 기능은 별도 브랜치에서 다룬다.
