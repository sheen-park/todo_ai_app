# AI 파싱 품질 회귀검증 테스트 케이스

## 목적

`build_ai_parse_prompt()`를 수정할 때마다 기존 품질이 깨지지 않았는지 확인하기 위한 수동 테스트 케이스 모음이다.  
자동 테스트가 아니라 사람이 앱에 직접 입력하고 결과를 비교하는 기준 문서다.

---

## 공통 통과 기준

- title만 보고 다음 행동을 알 수 있어야 한다.
- `@태그`는 title 맨 마지막에만 있어야 한다. `@태그` 뒤에 텍스트가 오면 안 된다.
- `memo`에는 기준일, 파싱, 추정, AI가, 배분 같은 시스템 설명이 없어야 한다.
- 분해 ON이면 복합 업무는 2~5개 정도로 자연스럽게 분해한다.
- 분해 OFF이면 반드시 1개 후보만 표시한다.
- 날짜는 전체 기간 안에서 순차 배분되어야 한다.
- 날짜 형식은 `YYYY-MM-DD`를 유지한다.

---

## 실패로 볼 패턴

| 패턴 | 설명 |
|---|---|
| 모든 업무가 초안/검토/최종안 | 여행·행사·특강·대회가 문서형처럼 처리됨 |
| title이 비슷하고 memo에만 차이 | 단계 차이가 title에 드러나지 않음 |
| 추상 title | "운영 요소 점검", "준비사항 정리", "관련 내용 확인" 등 구체 대상 없음 |
| 핵심 목적어 탈락 | title에서 대상(강사, 참가팀, 심사표 등)이 사라짐 |
| 최종 행위만 단독 title | "증빙 제출", "명단 제출"처럼 사전 수합·확인 단계 없음 |
| @태그 위치 오류 | `@태그`가 title 중간에 있거나 `@태그` 뒤에 텍스트가 붙음 |
| 과분해 | 단순 행정 업무가 5개 이상으로 쪼개짐 |

## 테스트 케이스

### TC-01 보고서형 (문서 산출물)

**입력**
```
AAA 보고서를 5월 15일까지 작성해야 해. 초안 만들고 검토 후 최종본으로 만들 거야. @kca
```

**기대 출력**
```
- AAA 보고서 초안 @kca
- AAA 보고서 검토 및 수정 @kca
- AAA 보고서 최종본 @kca
```

**통과 기준**
- 문서형이므로 초안/검토/최종본 구조 허용
- 날짜가 5월 15일 이전으로 순차 배분
- `@kca`가 각 title 맨 마지막

---

### TC-02 여행 계획형

**입력**
```
이번달 말 제주도 가족여행 계획짜기 @family
```

**기대 출력**
```
- 제주도 가족여행 일정 후보 정리 @family
- 제주도 가족여행 교통·숙소 확인 @family
- 제주도 가족여행 방문지·식당 리스트 정리 @family
- 제주도 가족여행 준비물 및 예약 최종 확인 @family
```

**통과 기준**
- "초안/검토/최종안"이 나오면 실패
- 여행 단계에 맞는 구체 대상(일정, 숙소, 방문지 등)이 title에 포함
- 4개 전후 (3~5개 허용)

---

### TC-03 특강 운영형

**입력**
```
다음달 학과 AI 특강 운영 준비. 중요도 상. @sw
```

**기대 출력**
```
- 학과 AI 특강 강사 일정 확정 @sw
- 학과 AI 특강 홍보문 작성 및 발송 @sw
- 학과 AI 특강 참석자 신청 명단 정리 @sw
- 학과 AI 특강 강의자료 수합 및 장비 점검 @sw
- 학과 AI 특강 당일 운영 체크리스트 작성 @sw
```

**아쉬운 출력 (통과 불가)**
```
- 학과 AI 특강 자료·장비·장소 준비 @sw       ← 대상 3개 이상 묶임
- 학과 AI 특강 당일 운영 및 사후 정리 @sw    ← "사후 정리" 무엇인지 불명확
- 학과 AI 특강 운영 요소 점검 @sw            ← 추상 표현
```

**통과 기준**
- 각 title에 구체 대상(강사, 홍보문, 참석자, 강의자료 등) + 실행 행위 포함
- "자료·장비·장소"처럼 대상 3개 이상을 한꺼번에 묶지 않음
- 5개 전후 (4~6개 허용)

---

### TC-04 창업경진대회 운영형

**입력**
```
1달 뒤 진행할 교내 창업경진대회 진행을 준비를 해야해. @sw 중요도 상.
```

**기대 출력**
```
- 교내 창업경진대회 모집 공고 및 접수 양식 준비 @sw
- 교내 창업경진대회 심사위원 섭외 및 심사표 작성 @sw
- 교내 창업경진대회 참가팀 접수 확인 및 안내 @sw
- 교내 창업경진대회 본선 당일 운영 시나리오 작성 @sw
- 교내 창업경진대회 결과 발표 및 수상자 후속 안내 @sw
```

**통과 기준**
- 이해관계자(심사위원, 참가팀)와 운영 산출물(시나리오)이 title에 포함
- "초안/검토/최종안" 구조가 나오면 실패

---

### TC-05 행정/증빙형

**입력**
```
다음주까지 출장비 정산서 작성하고 영수증 첨부해서 제출해야 해.
```

**기대 출력**
```
- 출장비 정산서 작성
- 출장비 영수증 첨부 및 제출
```
또는
```
- 출장비 정산서 작성
- 출장비 영수증 첨부자료 정리
- 출장비 정산서 제출
```

**통과 기준**
- 사용자가 명시한 행동(작성, 첨부, 제출)이 title에 반영됨
- 2~3개 후보 (5개 이상이면 과분해)

---

### TC-06 법인카드 증빙형

**입력**
```
다음주까지 법인카드 사용 내역 정리하고 증빙 제출해야 해. 중요도 중.
```

**기대 출력**
```
- 법인카드 사용 내역 확인 및 정리
- 법인카드 증빙자료 수합 및 제출
```

**아쉬운 출력 (개선 필요)**
```
- 법인카드 사용 내역 정리     ← "확인" 단계 누락
- 법인카드 증빙 제출          ← 수합 단계 누락, 최종 행위만 단독 title
```

**통과 기준**
- 최종 행위("제출") 앞에 수합/확인 단계가 title에 포함
- 2개 후보

---

### TC-07 안내문 작성/발송형

**입력**
```
다음주까지 행사 안내문 작성하고 참석자에게 발송해야 해. @sw
```

**기대 출력 (둘 다 허용)**
```
- 행사 안내문 작성 @sw
- 행사 안내문 참석자 발송 @sw
```
또는
```
- 행사 안내문 작성 및 참석자 발송 @sw
```

**통과 기준**
- 작성과 발송 두 행위가 title에 반영됨
- 1~2개 후보

---

## 분해 ON/OFF 검증 기준

### TC-08 분해 OFF

**입력**
```
[AAA보고서] 5월 1일부터 5월 15일까지 만들어야 해. 초안을 만들고 검토 및 수정하고 최종안으로 만들거야. 매우 중요하고 @kca 관련 일이야
```

**분해 OFF 기대**
- 후보는 반드시 **1개**
- title 예: `[AAA보고서] 작성 @kca`
- 세부 단계(초안·검토·최종안)는 memo에 간단히 포함

**분해 ON 기대**
- 3개 후보 (초안 / 검토 및 수정 / 최종본)

**통과 기준**
- 분해 OFF일 때 2개 이상 후보가 나오면 실패

---

## @태그 검증 기준

| 항목 | 기준 |
|---|---|
| 원문에 `@sw`가 있으면 | 모든 후보 title 맨 마지막에 `@sw` 유지 |
| 원문에 `@태그`가 없으면 | 임의로 `@태그` 추가 금지 |
| `@태그` 뒤 텍스트 | 없어야 함 |
| 미등록 `@태그` 입력 시 | 저장 적용 전 등록 여부 UI 표시, 등록 후 적용하면 `roles.json`에 추가, 등록 없이 적용하면 미분류 처리 |

**미등록 @태그 테스트 입력**
```
이번주까지 질문의기술 B2B과정 강의안 작성완료. 상. @how로 분류
```
- title 마지막에 `@how` 유지
- 적용 버튼 클릭 시 미등록 `@how` 안내 UI 표시

---

## memo 검증 기준

| 허용 | 금지 |
|---|---|
| 실제 업무 수행에 참고할 내용 | "기준일 기준으로 배분", "추정", "AI가 분석", "파싱 결과" |
| 간단한 단계 요약 (분해 OFF) | 날짜 계산 근거 |
| 빈 문자열 `""` | 시스템 메타 설명 |

---

## 날짜 배분 검증 기준

- 각 후보의 `start_date <= due_date`
- 후보 간 날짜가 겹치지 않고 순차적으로 이어짐
- 마지막 후보의 `due_date`는 전체 최종 마감일과 일치
- 기간이 너무 짧으면 후보 수를 줄임 (1주 이내 → 1~2개)
